Projects

Smart Campus Lost & Found

full-stack · campus tool

React · TypeScript · NestJS · PostgreSQL · Prisma · Redis · Socket.IO · Docker

the problem
Lost items on campus mostly circulated through notice boards, WhatsApp groups, and word of mouth — and there was no way to verify a claim before someone handed an item over.
what I built
A role-based app for students, faculty, security, and admins to report and claim items, with real-time updates when the system finds a likely match.
technical calls
The core problem was matching, not CRUD. Exact string matching doesn't work for lost items — "blue water bottle" and "navy bottle, dented cap" should still match — so items are scored on keyword similarity, category, location, and how close the report and claim dates are. Claim status updates run over Socket.IO instead of polling, and the REST layer sits behind JWT auth with Redis caching on the endpoints that get hit most.

AI Resume Analyzer

full-stack · AI

React · Node.js · Google Gemini API · REST APIs · Vercel · Render

the problem
Most resume feedback is generic ("add action verbs") and doesn't actually check your resume against the job you're applying for.
what I built
A tool that takes a resume and a target job description and returns keyword gaps, an ATS-style compatibility score, and specific edit suggestions — with a dashboard to keep track of different resume versions.
technical calls
The hard part wasn't calling the Gemini API, it was keeping the scoring consistent across resumes instead of just rewarding whichever one happened to be better written. Parsing, scoring, and suggestion generation each live behind their own route so they can be changed or scaled independently, and the frontend and backend are deployed separately (Vercel / Render) rather than as one app.

FinFlow

full-stack · personal project

React · Node.js · Express · MongoDB · Tailwind CSS · Chart.js

the problem
I wanted an actual picture of where money was going every month, instead of reconstructing it from bank statements after the fact.
what I built
A personal finance tracker that classifies transactions, tracks budget targets by category, and charts spending trends and distribution over time.
technical calls
Transaction classification and monthly aggregation happen server-side so the charts stay responsive regardless of how much history is loaded. Auth and financial records go through JWT-protected routes with encrypted storage, since this handles real (if personal) financial data rather than dummy records.

E2E-Self-Heal

open source · CLI

TypeScript · Node.js · GitHub Actions · CLI · pytest

the problem
Setting up CI for a new project usually means hand-writing GitHub Actions config before you can run a single test.
what I contributed
The init CLI command for an existing open-source self-healing test framework, which scaffolds GitHub Actions workflow files automatically instead of requiring manual setup.
technical calls
Cross-platform path resolution was the annoying part — file paths that worked fine on Linux CI runners broke on Windows. Wrapped the generation logic in structured try/except handling so a bad path fails loudly instead of silently corrupting the workflow file, and added pytest integration tests that check the generated files instead of relying on manual review.
